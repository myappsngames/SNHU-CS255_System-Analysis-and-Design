# SNHU CS-255 Journal (DriverPass Project)
DriverPass


* Briefly summarize the DriverPass project. Who was the client? What type of system did they want you to design?
  
  * DriverPass, a driver education company, requires a modern system to manage their online and in-person training program. DriverPass wants their system to streamline the student driver experience by offering online registration, lesson scheduling, and progress tracking. DriverPass will allow a student driver to easily enroll online, choose a package that fits their needs, and schedule lessons at their convenience. The DriverPass system goes beyond student empowerment, equipping instructors and administrators with functionalities like lesson tracking and reporting.
    
* What did you do particularly well?
  
  * Strengths of the Design:
    
    * User-Centric:
      
      * DriverPass caters to different user roles (student, instructor, secretary, admin, owner) with specific functionalities for each.

    * Streamline Processes:
      
      * DriverPass streamlines online registration, package selection, lesson scheduling, and progress tracking.
        
* If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?
  
  * While the initial design considers user needs based on interviews and sketches, incorporating formal UX testing would significantly improve the system’s usability. For example, DriverPass could incorporate user testing sessions, develop test scenarios, observe user interactions, and iterate on design.
     
* How did you interpret the user’s needs and implement them into your system design? Why is it so important to consider the user’s needs when designing?
  * The project began with an interview with DriverPass representatives. This initial discussion helped understand their vision for the system and the functionalities they desired (e.g., online registration, lesson scheduling, reporting). Client-provided materials also provided valuable insights into the user interface layout and desired functionalities.
      
  * I implemented the user’s needs into a role-based design. The system design considers different user roles and assigns functionalities based on their needs.
      
  * It is important to consider the user’s needs to create a user friendly system. The system should be catered to the specific task each user group needs to perform. This strategy increases early adoption and user satisfaction. Creating a user-centric design by identifying and addressing user needs upfront can also reduce development costs. A user-centric design avoids building unnecessary functionalities, saving time and resources during development.
    
* How do you approach designing software? What techniques or strategies would you use in the future to analyze and design a system?
  
  * I approach designing software by first gathering and analyzing system requirements. Based on the gathered requirements I create a system architecture with functionalities mapped to user roles. Finally, I develop system components and test them for functionality and integration.
    
  * In the future, I would use Joint Application Design (JAD) Sessions where stakeholders from different areas come together to define system requirements. Implementing JAD sessions increases production by defining system requirements early on. I would also use rapid prototyping. I think this is a great design technique to implement as prototypes can be used for user testing and feedback to identify issues before extensive development begins.
